Инструкция по обновлённым заданиям «ПР5_Django_Base (1).pdf» и
«ПР6_Django_Shablony (1).pdf», проверенным 11 октября 2026 года.
Это памятка к демонстрации, а не замена отчётам и прохождению курса.

В ПР6 новых функциональных требований при сравнении редакций не обнаружено:
добавлена таблица оценивания. Уже реализованы шаблоны, контекст, циклы и условия,
пустые коллекции, URL namespace, фильтры, CSS, изображение и JavaScript.
Доработка 404 совместима с ПР6: HTML находится в шаблоне, а не в Python.

Roomly в методичке — пример, а не требование переименовать индивидуальный проект.
В примечаниях к таблицам оценивания прямо разрешена демонстрация на своей предметной
области. Здесь помещениям соответствуют события (`Event`), а связанным бронированиям —
задачи подготовки (`Task`, связана с `Event`). Вместо доступности помещения показываем
состояние бюджета события; вместо статуса бронирования — статус задачи.
Дополнительные участники и расходы сохраняются. Django ORM, формы, регистрацию
и редактирование в браузере на этих этапах внедрять не требуется.

## Правила защиты и что подготовить

Для каждой работы индивидуальный проект оценивается отдельно от курса:
25 показателей × 0,05 балла = максимум 1,25 балла. Опрос идёт по порядку таблицы,
длится не более 5 минут и заканчивается на первом неправильном ответе или
отсутствии ответа. Это правило из методичек, а не прогноз оценки.

До занятия:

1. Пройди предусмотренные материалы Яндекс Практикума в своём аккаунте; приготовь
   возможность показать преподавателю результат. Чек-листы ниже отмечай только
   после фактического выполнения. HomeParty не заменяет проект «Блогикум» в курсе.
2. Приготовь два отчёта: ПР5 и ПР6, каждый на 1–2 страницы основного текста
   плюс титульная информация. Скриншоты в этих требованиях к отчётам не обязательны.
   В ПР6 должны быть вариант, результаты проверок и коммит с префиксом `PR6:`.
3. Открой репозиторий в редакторе, терминал в его корне, браузер с сайтом и курс.
   Проверь, что можешь быстро найти файлы из таблиц ниже.
4. Выполни команды проверки и заранее запусти сервер. Пройди страницы и ссылки.
5. Подготовь историю Git: `b21d0d9` — исходный этап ПР5, `8ec0569` — исходный
   этап ПР6; последующие коммиты содержат дополнения по обновлённым заданиям.
   Не переписывай старую историю и не возвращай `page()` в ПР6.
6. Отрепетируй каждый пункт по порядку: короткий ответ и немедленный показ кода.
   Практические изменения заголовка/статуса делай только по просьбе преподавателя
   и после демонстрации верни исходный текст вручную в редакторе.

Методички задают отчёт, демонстрацию, Git и проверку курса. Конкретная система
загрузки файлов, дедлайн и необходимость прикреплять архив там не указаны — это
нужно уточнить у преподавателя. Для передачи приготовь DOCX и ссылку на репозиторий;
не выдавай эту рекомендацию за требование загрузить их на конкретный сайт.

## Запуск и проверки на Windows

Открой PowerShell в корне **HomeParty**, а не в родительской папке.
Команды ниже не требуют активации окружения или изменения ExecutionPolicy.

Если окружения ещё нет (на своём компьютере повторно создавать его не нужно):

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
```

Перед защитой:

```powershell
.\.venv\Scripts\python.exe -m django --version
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 . --extend-exclude=venv
git status
git log -5 --oneline
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

`check` проверяет конфигурацию, но не открывает сайт и не запускает сервер.
`runserver` принимает HTTP-запросы; оставь этот терминал работающим.
Сервер останавливается `Ctrl+C`. Если порт занят, используй свободный порт,
например `8002`, и тот же порт в адресе браузера. Предметные данные остаются
в JSON; миграции создают только стандартные таблицы Django.

### Что открыть в браузере

| Адрес на `http://127.0.0.1:8000` | Что показать |
| --- | --- |
| `/` | Описание HomeParty, навигация, счётчики реальных данных |
| `/events/` | Список событий, карточки, ссылки на детали |
| `/events/1/` | Название, дата, бюджет, расходы, участники, открытые задачи |
| `/tasks/` | Список задач, связанные события, два состояния статуса |
| `/tasks/1/` | Задача «Заказать торт», статус «Выполнена», ссылка на событие |
| `/tasks/2/` | Задача «Украсить комнату», статус «В работе» |
| `/participants/`, `/expenses/` | Дополнительные разделы индивидуального проекта |
| `/events/999/`, `/tasks/999/` | Маршрут существует, но объекта нет: специальное сообщение и HTTP 404 |

Идентификаторы соответствуют сохранённым демонстрационным JSON. Если данные
изменены, выбирай существующие ID из списков, а отсутствующий ID — после проверки данных.

### Как показать общую 404 из обновлённой ПР5

Во втором терминале, также из корня HomeParty:

```powershell
.\.venv\Scripts\python.exe manage.py check --settings=homeparty.settings_demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001 --settings=homeparty.settings_demo --insecure
```

Открой `http://127.0.0.1:8001/nonexistent/` и `/events/abc/`. Появятся
оформленная страница «404 — Страница не найдена» и ссылка на главную.
В DevTools браузера на вкладке Network посмотри статус основного запроса: `404`,
а не `200`. Или во втором свободном терминале:

```powershell
curl.exe -s -o NUL -w '%{http_code}' http://127.0.0.1:8001/nonexistent/
```

`settings_demo.py` наследует основные настройки и меняет только `DEBUG=False`.
В `ALLOWED_HOSTS` уже есть `127.0.0.1` и `localhost`; `testserver` нужен тестовому
клиенту. При неподходящем Host Django вернёт 400, а не нужную страницу 404.
`--insecure` позволяет встроенному серверу локально раздавать static при
`DEBUG=False`. **Не используй этот режим для публикации сайта в интернете.**
Без него HTML-обработчик 404 тоже работает, но CSS, JS и изображение не раздаются
обычным development-сервером при отключённой отладке.

Не нужно менять `DEBUG` в основном файле и потом забывать вернуть значение:
обычный запуск на 8000 сохраняет `DEBUG=True` и техническую страницу для отладки.
При `DEBUG=False` неизвестный маршрут или исключение `Http404` попадают в
`handler404`. Явный `render(..., status=404)` в деталях события/задачи уже является
готовым ответом и не запускает этот обработчик повторно.

### Репетиция перед ПР6

За 5 минут не читай памятку вслух. Держи открытыми файлы и отвечай по вопросу:
сначала точный ответ, затем соответствующая строка кода. Потренируйся укладывать
